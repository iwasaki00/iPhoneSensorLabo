# エアギャップ通信実験室（Signal Lab）

**Signal Lab - Frequency Test**  
**Version 0.1.1 — SIGNAL STABILIZATION**

スマートフォンの周波数発生・マイク受信・FFT解析を行う静的Webアプリです。外部ライブラリ、外部API、解析サービスは不要です。文字列通信や通信プロトコルは実装しません。

## ファイルと起動

- `index.html`: GENERATOR / RECEIVER / SWEEP / LOG画面
- `style.css`: スマホ縦向きの暗色UI
- `main.js`: Web Audio、マイク、グラフ、スイープ、ログ、リソース管理
- `analysis.js`: RAWピーク、中央値安定化、時間ベースのロック管理、判定、差分、スイープ列、CSV生成
- `tests.cjs`: 合成データの解析テスト
- `browser-tests.cjs`: ヘッドレスChromiumのUI・Web Audio統合テスト
- `README.md`: 操作と検証手順

このフォルダを単体でGitHub Pages等のHTTPS静的ホスティングへ配置してください。実行には最初の4ファイルのみ必要です。親フォルダに依存しません。既存実験メニューにも入口を追加しています。

PCローカル検証はリポジトリルートで `node server.js` を実行し、`http://localhost:8123/air-gap/` を開きます。スマートフォンからPCのLAN IPへHTTPでアクセスしても、マイクの安全なコンテキスト要件を満たしません。実機ではHTTPSを使ってください。

ページ取得・更新以外に通信はありません。音声はブラウザ内で処理し、外部送信・録音・保存は行いません。Service Workerによるオフラインキャッシュは未実装です。

## 基本操作

### GENERATOR

1. 端末本体の音量を低くします。ページの初期音量は5/100、実ゲイン0.0075です。
2. 100〜20,000Hzの整数を入力、スライダー、±10/100/1000Hz、プリセットで選びます。
3. STARTでSine波を発音、STOPで停止。発音中も周波数・音量を変更できます。

最大ゲインは0.15です。実際の音圧上限を保証するものではありません。ナイキスト周波数以上は拒否します（32kHzサンプルレートなら15,999Hzが上限）。開始・停止は約25msでフェードし、自動発音はしません。15kHz以上で注意文を表示します。高周波が人に聞こえないとは限りません。

### RECEIVER

1. TARGET FREQUENCYを設定（例：17000Hz）。空欄は未設定です。
2. 許容誤差を±Hzで設定（初期50Hz、1〜2000Hz）。FFTは初期16384、負荷に応じ8192へ切り替えます。
3. MIC STARTでマイクを許可。MIC STOPで全トラックを停止します。
4. 大きなSTABLE FREQUENCY、診断用RAW PEAK（全帯域最強ピーク）、状態、品質、ターゲット付近の強度、差分Hz/%、入力RMS、ノイズフロア、SNR参考値を確認します。ターゲット設定時のRAW候補はLAB内に表示します。
5. 全帯域または15〜20kHz拡大表示を選択。最大ピークは黄、ターゲットは紫。波形は約10msの画素ごとの最小・最大振幅です。

`echoCancellation`、`noiseSuppression`、`autoGainControl`は対応時に`ideal: false`を要求します。制約エラー時は制約なしで再試行。「マイク処理の適用状況」に対応・要求・実適用値を表示し、取得できない値は「不明」とします。要求が実際に適用されるとは限りません。

受信音はスピーカーへ再生しません。解析グラフ維持のための出力接続はゲイン0です。背景移行・pagehide・AudioContext割り込み・マイク終了時に停止し、復帰後はSTART/MIC STARTで明示的に再開します。停止・設定変更で古い測定値をクリアします。

「LAB · 安定化 / DEBUG」は通常閉じて使います。安定化ON/OFF、中央値3/5/7/9フレーム、ロック最短100〜1000ms、保持上限100〜2000msを設定できます。初期値はON・5フレーム・100ms・300ms。設定変更で履歴をリセットし、無効な設定は前の値に戻します。OFF時の大表示はRAW FREQUENCYとなり、現在の有効候補をそのまま表示します。STABLE値は未検出として扱い、ログにもOFFを記録します。時間ベースの信頼性判定はOFFでも維持します。

| 受信状態 | 意味・表示 |
| --- | --- |
| SEARCHING | 強い候補を確認中。ロック前は安定値を表示しない |
| LOCKED | 継続・強度・周波数一致条件を満たす現在の受信。DETECTEDに対応 |
| WEAK | 弱い有効候補はあるが確信できない。安定値は表示しない |
| LOST | 過去のロックを失った。現在受信中を意味せず、安定値は即座に消える |
| NO SIGNAL | 有効候補なし。保持上限を過ぎた古いロックも破棄済み |

品質はGOOD（現在ロック）、FAIR（強い候補を探索）、LOW（弱い候補）、NONE（有効候補なし）の参考表示です。正解確率や通信品質を保証する値ではありません。LOST中に保持する内部値は再捕捉用であり、画面やCSVに現在の安定値として出力しません。

### SWEEP

- A：500、1000、2000、4000、8000、12000、15000、16000、17000、18000、19000Hzの順。
- B：開始≦終了、整数ステップを指定。終了がステップに一致しない場合は終了を超えない最後の値まで。最大1000ステップ。
- 出力時間0.1〜30秒、無音時間0〜30秒。SWEEP START/STOPで開始・中止。
- GENERATORと同じ音量を使用し、通常発音とは排他。停止フェード後に指定無音時間を確保するため、各ステップに約35msの遷移時間を追加します。タイマー精度は端末状態に依存します。
- 受信側は独立動作。他端末の設定を自動取得せず、ターゲットは手動設定します。

### LOG

RECEIVERの「測定結果を手動記録」で、日時、ターゲット、検出値、差分Hz/%、受信強度、ノイズフロア、状態、解析サンプルレート、FFTサイズを記録します。NO SIGNALも記録でき、検出・差分は空欄。未設定ターゲットは「未設定」です。

LOGからExcel向けCSV（UTF-8 BOM付き、CRLF改行、引用符エスケープ）をダウンロードできます。日時はUTCのISO 8601（末尾Z）。ログはメモリ内のみで最大1000件、再読み込み・終了時に消えます。音声は保存しません。

従来の先頭10項目と順序を維持し、RAW PEAK、STABLE FREQUENCY、受信状態、品質、安定化ON/OFF、RAW候補、実効許容誤差、検出継続msを末尾に追加しています。従来の「検出状態」はDETECTED/WEAK/NO SIGNALを維持し、新しい5状態は「受信状態」に保存します。「検出Hz」と差分はONなら安定値、OFFなら有効RAW候補から計算。安定値・検出値が存在しない場合は空欄とし、0Hzで代用しません。UIには「未検出」と表示します。全帯域RAWピークは診断用なので、ターゲット不在時に別の音やノイズを指すことがあります。

## v0.1.0の確認と変動原因

利用者から、v0.1.0では500〜15,000Hzの送受信と周波数検出に成功した一方、受信数値が頻繁に変動すると報告されています。この報告は実機での確認です。v0.1.1の実機改善はまだ確認していません。

改修前の処理を確認した結果、FFTビンのHz換算は `bin * sampleRate / fftSize` で正しく、隣接3ビンのdB放物線補間も実装済みでした。ノイズフロアはピーク周囲の中央値、平滑化は0です。ただし4フレームの振れ幅チェックは状態表示だけに使われ、数値には毎フレームのRAW補間値を直接表示していました。雑音による最大ビンの交代と補間値の揺れが、そのまま表示に現れる構造が主な推定原因です。またターゲット帯域の端で、帯域外ピークの裾を候補にする可能性がありました。実機波形を取得した原因の確定ではありません。

今回もFFT計算・Hz換算・補間を再利用し、同じ音を別の解析処理で重複計算しません。発生器、プリセット、スイープ、音量制限、権限管理、停止時の解放処理は維持しています。

## 解析方法・既知の制約

- Web Audio AnalyserNodeのFFT（Blackman窓）、平滑化0、実AudioContext.sampleRateを使用。
- 分解能は `sampleRate / fftSize`。48kHz/16384 ≈ 2.930Hz、48kHz/8192 ≈ 5.859Hz。小数点表示は精度保証ではありません。
- ピークと隣接2ビンのdB値で放物線補間。ターゲットありでは実効誤差帯域内の局所最大を優先し、帯域境界の単なる裾を除外。存在しないピークを推測しません。実効許容誤差は `max(入力したHz, 1.5 * FFT分解能)`。入力欄の互換性を保ち、実効値はLAB/CSVで確認できます。
- 周囲約±500Hz（最低±24ビン、ピーク±5ビンを除く）の中央値をノイズフロア、その差をSNR参考値とします。
- ピーク>-85dBFS、入力RMS>-75dBFS、SNR≧6dB、ターゲット範囲内で候補。条件外はNO SIGNAL。
- 強い有効候補（SNR≧12dB）を近い周波数のクラスタとして保持し、初期は連続3解析以上かつ100ms以上でロック。現在クラスタの振れ幅は `2 * max(1.5ビン,3Hz)` 以内に制限します。
- ロック中は `max(1.5ビン,3Hz)` 内の有効候補の直近5値を中央値で表示。遠い外れ値は混ぜず、安定表示を一旦消します。新周波数が3解析・100ms継続すれば別クラスタで再ロックし、旧履歴を混ぜません。
- 無効・弱いフレームでは現在の安定値を即座に消し、内部ロックは最後の一致から初期300msで破棄。弱い信号はWEAK、ロック後の消失はLOSTからNO SIGNALへ遷移します。短い欠落後に同じ強い音が戻った場合は保持中のロックを再利用します。
- 解析は最大20fps。状態判定にはrequestAnimationFrameの単調時刻をミリ秒で使い、描画数をカウントしません。同時刻の重複呼び出しはロック回数を増やさず、保持時間を超える解析間隔では履歴をリセットします。ロック継続時間は中央値窓とは別に管理するので、長いLAB設定でもロック可能です。
- FFT窓は重なるため各フレームは独立測定ではありません。48kHz/16384の窓は約341ms、8192は約171ms。物理的な音の変更からの反応時間にはFFT窓と解析待ちも加わります。FFTの平滑化0は維持し、時間平均による周波数変更のにじみを追加しません。
- FFTビン強度は窓処理を含むデジタル参考値で入力RMSとは異なります。いずれも音圧dB SPLではありません。SNRも校正された帯域積分値ではありません。
- 環境内の別の安定音も検出され得ます。あらゆる雑音の誤判定防止は保証できません。
- 16〜20kHzの可否はスピーカー、マイク、OS処理、端末音量、距離に依存。ナイキスト条件を満たしても実際の出力/受信を保証しません。

## 自動テスト

リポジトリルートで実行します。

```sh
node --test air-gap/tests.cjs
node air-gap/browser-tests.cjs
```

フォルダ単体では `node --test tests.cjs` / `node browser-tests.cjs` です。解析はNode組み込みテストランナーのみ。ブラウザ検証にはWebSocket/fetch対応Node.js（22以降推奨）とローカルChrome/Edgeが必要です。自動検出できなければ環境変数`CHROME_PATH`を指定します。追加npmパッケージは不要です。

- **解析71件成功（従来45件を維持、26件追加）**：従来の合成正弦波、100Hz境界、15〜20kHz、32/44.1/48kHz、FFT8192/16384、補間、無音、雑音、差分、スイープ列、CSVに加え、1000/15000Hzロック、添加雑音、瞬間的な強いノイズ、複数音混在、弱いターゲット、帯域外ピークの裾、1Hz入力時のFFT対応許容、1000→2000Hz変更、信号停止、連続白色雑音、スイープ追従、ON/OFF、同時刻/不規則時刻、設定変更、長いロック時間、短い信号、拡張ログを検証。
- **ヘッドレスChrome37件成功（従来26件を維持、11件追加）**：従来の発生・スイープ・マイク管理・停止・グラフ・ログの回帰検証に加え、RAW/STABLE表示、LOST時の値消去、LAB ON/OFF、設定検証/復元、ターゲット変更時の再捕捉、拡張CSV、LABを開いた320px縦画面を確認。
- 未捕捉ブラウザ例外なし。生成・受信画面のモバイル幅スクリーンショットを目視確認。
- ブラウザ検証は音声出力をミュートし、マイクAPIを合成ストリームに置換。**実マイク・実スピーカーの測定ではありません。** ユーザー操作も模擬しており、Safariの開始制限は実機確認が必要です。

### 安定化前後の合成データ比較

| 条件 | RAW / 従来の直接表示 | 安定化ON |
| --- | --- | --- |
| 1000Hz、振幅0.04、一様白色雑音±0.08、48kHz/16384、50ms間隔80フレーム（後半70フレーム評価） | 変動幅0.2154Hz | 変動幅0.0829Hz、約61.5%減、ロック継続 |
| 1000→2000Hzへ変更、更新50ms | 新しいFFT結果の最初からRAW変更 | 最初の新FFT結果から100msで再ロック。途中は旧安定値を出さない |
| 1フレームだけ7000Hzの強い妨害音 | RAW PEAKは約7000Hzへ移動 | 安定値を未検出にし、1000Hz復帰時に再捕捉。妨害を安定値として出さない |
| ロック後の合成無音 | RAW有効候補なし | 即座に値消去・LOST、最後の一致から300msでNO SIGNAL |

比較は固定シードの合成FFTスナップショットによるものです。雑音や距離が変われば改善幅も変わります。追従100msはFFT取得後のアルゴリズム時間で、実機の音響遅延やFFT窓内の旧音の残留を含みません。最小出力0.1秒のスイープはロック時間とFFT窓より短く、SEARCHING/WEAKのまま終わり得ます。安定値の確認には出力0.5〜1秒以上を使ってください。RAWは短い信号でも診断できます。

## 2台の実機で試す手順

1. HTTPSで公開し、送信・受信の2台で開きます。機種、OS/ブラウザ、端末音量、距離も別途メモします。
2. 受信側でTARGET=1000Hz、許容±50Hz、FFT=16384に設定。MIC STARTで許可し、送信停止時のNO SIGNALと環境雑音を確認します。
3. 送信側で1000Hz、初期低音量のままSTART。数秒待ち、受信値・強度・SNR・状態を手動記録。STOP後にNO SIGNALへ戻ることを確認します。
4. 発音中に1000→2000Hzと音量を変更し、受信ターゲットも2000Hzへ手動変更して確認します。
5. 双方を16000、17000、18000、19000Hzへ順に設定。必要なら20000Hzも直接入力。低音量で試し、検出できない場合も記録します。高周波拡大表示・FFT8192も比較します。
6. SWEEP Aの順序・進行・STOPを確認。Bは15000→19000、1000Hz刻み、出力1秒、無音0.5秒で試します。受信側は独立測定し、ターゲット未設定なら最強ピークの推移を見られます。
7. CSVを保存してExcelで日本語・未設定・NO SIGNAL・数値を確認します。
8. 権限拒否の案内、MIC STOP後のマイク解除、背景移行・画面ロック・着信等での停止、復帰後の手動再開を確認。送受信端末を入れ替えて再試験します。

### v0.1.1の実機再確認

同じ機種・距離・音量で1000Hzを数秒出し、LAB ON/OFFでRAW候補と大表示の変動を比較してください。次に受信ターゲットを空欄にして1000→2000Hzへ送信を変更し、SEARCHINGを経て新しいLOCKEDへ移ることを確認します。ターゲットを1000Hzに固定したまま2000Hzへ変更した場合は、ターゲット不在としてLOST/NO SIGNALになるのが正しい動作です。短い妨害音・弱い音・停止後の状態も記録し、500〜15,000HzおよびFFT8192/16384で再試験してください。CSVのRAW/STABLE/状態/ON-OFFも比較できます。
