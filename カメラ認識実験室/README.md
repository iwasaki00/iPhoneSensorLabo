# Camera Vision Lab — カメラ認識実験室

Version **0.8.0 / DEPTH LAB**。iPhone Safariを優先した認識技術の実験ツールです。既存の認識・文字・マーカー・ARカード・シミュレーターを維持し、静止画1枚から相対的な奥行きを推定する実験を追加しました。無料のブラウザ内処理で動作し、映像・画像・推定マップを外部に送信しません。

## 起動

Node.js 22.18以上（検証環境25.9.0）、npmを使用します。

```sh
cd カメラ認識実験室
npm ci
npm run assets
npm run dev
```

PCは表示された `http://localhost:5173` を開きます。iPhoneからPCのHTTP LANアドレスを開くとカメラを使用できません。iPhoneには**信頼された証明書でのHTTPS配信**が必要です。[実機手順](docs/IPHONE_CHECKLIST.md)を参照してください。

```sh
npm test
npm run build
npm run preview
npx playwright test tests/browser/textmarker.spec.ts
```

最後のコマンドはPCにインストール済みのChromeと模擬カメラを使用する関連ブラウザテストです。実カメラの認識精度を保証するものではありません。

## 操作

### 奥行き認識（v0.8.0）

1. 「認識モード」→ **奥行き認識**。端末内画像を選びます。ファイルだけならカメラ権限は不要です。カメラを使う場合は手動で起動し「カメラから1フレーム取得」を押します。PNG/JPEGなど、ブラウザで表示できる画像を使用してください。
2. **奥行きを解析** を押した時だけモデル・WASMを読み込み、1回推論します。初回の同一サイトからの取得は約39.7MB（許諾文含む配布総量）です。他の認識モード起動時には取得しません。連打は抑制し、画像差替え・モード切替時は処理と古い結果を破棄します。失敗時は案内を確認し、同じボタンか「認識を再試行」を押します。
3. **色分け**：元画像／奥行き色分けを切替。赤が手前、緑が中間、青が奥です。実写真で大きい生出力が手前になることを確認して表示を統一しています。距離や確率の値ではありません。
4. **2点の前後比較**：画像を2か所タップしてA・Bを置きます。周囲の中央値で比較し、画像内の出力範囲に対して差が小さい場合は「前後を判定しにくい」と表示します。画像を変えると点と結果を消し、異なる写真の値を比較しません。
5. **物陰に隠れるキャラクター**：ロボットをドラッグし、「手前 ↔ 奥」で奥行きを設定します。ロボットより手前と推定した写真の画素に重なる部分だけを隠します。隠れ処理ON／OFFで比較できます。位置・奥行き・表示操作では再推論しません。
6. BEFORE／AFTER／左右比較、前面カメラの反転は既存機能を共有します。モデル名・入力サイズ・読込／解析時間は「奥行きの設定・診断」にあります。初期長辺280px、高精細確認用392／518px。低解像度は細い輪郭を失いやすく、高解像度は時間とメモリを使います。

モデルは **Depth Anything V2 Small Q4 ONNX（Apache-2.0）**、実行は **ONNX Runtime Web 1.23.2（MIT）／Worker／単一スレッドWASM**です。特別なCOOP/COEPヘッダーなしでPC実行を確認しました。WebGPUは使いません。iPhone Safariの実動作は未確認で、Worker・WASM SIMD対応が必要です。透明なコップ、反射、細い輪郭、絵画などでは推定が崩れます。連続推論・実距離・3D空間固定は実装していません。

実写真の街路・花と空では大まかな前後を確認し、平面の絵画に奥行きを付ける失敗例も記録しました。**コップと箱の前後を入れ替えた指定写真の検証は未実施**です。[モデル選定・実測・検証範囲](docs/V0_8_0.md)と[ライセンス一覧](THIRD_PARTY_NOTICES.md)を参照してください。

関連確認を再現する場合：

```sh
node scripts/prepare-depth-validation.mjs
node --experimental-strip-types --test tests/depth.test.ts
npx playwright test tests/browser/depth.spec.ts
```

検証画像と比較用UINT8モデルはGit対象外の `depth-validation.local/` へ取得し、アプリやdistには同梱しません。実モデル結果と模擬マップのテストを別ケース・別記録にしています。

### 印刷せずにARカードを試す（v0.7.1）

メイン画面の「認識モード」横にある **ARカードを試す** を押します。既存のARカード実験へ移動しますが、カメラは自動起動しません。初期モードと従来の「文字・マーカー」→「ARカード実験」の経路は維持しています。

**PC＋iPhoneの場合**

1. PCで「カード画像を開く」を押して `ar-playground.html` を開きます。ロボット・スライム・バッテリーを白い領域でそれぞれドラッグし、表示／非表示、配置リセットができます。「PNGを開く」で個別画像も表示できます。「リンクをコピー」で同じカード表示ページを別端末へ渡せます。
2. iPhoneでは親メニュー → カメラ認識実験室 → ARカードを試す → カメラを起動を押し、**PC画面に表示したカードを撮ります**。2枚を近づけると反応します。白い余白を隠さないでください。
3. iPhoneのカメラには信頼されたHTTPSが必要です。`localhost` は同じ端末用なので別端末へ共有できません。両端末から到達できる配信先URLを使用してください。この作業では公開・HTTPS環境の新規構築は行っていません。カード表示自体はカメラを使いません。

**1台のみの場合**

1. ARカードを試す → **シミュレーター** を押します。直接 `ar-playground.html?mode=simulator` を開くこともできます。カメラ権限は不要です。
2. 3枚を個別にドラッグし、表示チェックで出し入れします。選択中のカードの大きさ・回転を調整できます。初期配置は離れており、自動で反応しません。
3. ロボット＋バッテリー、スライム＋バッテリー、ロボット＋スライムを試します。近づけたままでは1回だけ反応し、十分離してから再接近すると再反応します。一瞬隠すだけでは再発火しません。「配置をリセット」で位置・大きさ・回転・表示状態・判定・演出を初期化します。
4. 「カメラなし・模擬検出」の表示どおり、これは操作・判定・描画の確認用です。実際にカメラでマーカーを読めたことや、認識精度を示すものではありません。実カメラへ戻るリンクでもカメラは自動起動しません。

既存の3枚印刷とPNG保存は「印刷用・個別PNG」から利用できます。カード操作領域だけでスクロール・長押し選択を抑え、その外では通常のスクロール・選択を保ちます。[v0.7.1の設計と確認範囲](docs/V0_7_1.md)を参照してください。

### ARカード実験（v0.7.0）

親メニュー → カメラ認識実験室 →「文字・マーカー」→「ARカード実験」を選びます。

1. **カードを用意する**：開いたページで3枚を印刷するか、各カードの「個別PNGを保存」「このカードを大きく表示」を使い、別端末の画面に表示します。白い余白は切り落とさず、マーカーの上に絵や文字を重ねないでください。画像アップロード・素材登録は不要です。
2. **カメラを起動**：カメラを許可してカードを映します。ID 7＝ロボット、11＝スライム、19＝バッテリーです。検出した四隅に絵が現れ、移動・回転・傾きへ追従します。
3. **2枚を近づける**：ロボット＋バッテリーは充電、スライム＋バッテリーはふくらんでジャンプ、ロボット＋スライムは手を振ります。一度反応したら十分に離し、また近づけます。左右の順番は問いません。一瞬見失っただけでは再発火しません。

近さは画像上の中心間距離をカードの見かけの大きさで割った値です。物理距離や接触の測定ではありません。検出ID・割り当て・判定根拠・解析FPSは「カード実験の診断」にあります。未登録IDに絵は出しません。通常画面の件数は描画対象カード、診断は未登録を含む検出結果です。見失い・期限切れで合成が消え、停止・モード切替で演出と履歴を解放します。[カードと判定仕様](docs/V0_7_0.md)を参照してください。

PCでの関連確認は `node --experimental-strip-types --test tests/cards.test.ts tests/textmarker.test.ts` と `npx playwright test tests/browser/cards.spec.ts`。iPhone実機の確認は別途必要です。

### 文字・マーカー（v0.6.0）

1. 「認識モード」→「文字・マーカー」で実験を選択します。静止画はカメラ起動なしでも「端末内画像」から読み込めます。カメラ使用時は「カメラから1フレーム取得」を押します。OCRは静止画専用です。他の実験は「カメラ連続認識」も使えます。
2. OCRは日本語／英語／日英混在を選びます。「OCRの範囲・前処理」で切り取り範囲（元画像の%）、90度単位の回転、拡大、グレー／二値化を設定します。文字・行の枠と信頼度を表示し、前処理プレビューと元画像を比較できます。結果欄は編集・コピーできます。言語データは必要時だけ同一サイトから取得します。
3. QR／バーコードは形式・内容・検出点を表示します。同じ内容はまとめて検出回数を表示します。1回の解析で1コードです。URLは自動で開きません。編集・確認後に「URLを開く」を押したHTTP／HTTPSだけを開きます。商品検索は行いません。
4. 登録画像照合は「登録画像」で模様の多い平面画像を選び、別の入力画像かカメラと照合します。特徴点・一致数・RANSAC内点・四隅・2D回転を表示します。登録画像はメモリだけに保持し、「登録画像の明示保存」の保存ボタンを押した場合だけブラウザ内に保存します。読込・削除も明示操作です。
5. ARマーカーは **ARUCO_MIP_36h12、ID 0〜249** を使用します。「実験用マーカー」でIDを指定して生成し、PNG保存または印刷用画面を開きます。生成と検出は同じ辞書です。白い余白を切り落とさず、別画面または印刷でカメラに提示してください。
6. 「位置追従合成」はマーカー／登録画像を選び、文字・四角・円・端末内画像を平面に重ねます。画像上の四隅に追従する近似射影描画であり、3D位置・物理距離ではありません。合成は最大8面。見失った対象と期限切れ結果は解除します。
7. 「文字・マーカー詳細」で解析長辺320／640／960px、完了後待機100〜1000ms、自動／手動、有効期限を調整できます。自動は実測処理時間で最大5秒まで待機を増やします。重い場合は静止画を使ってください。
8. 通常／BEFORE／AFTER／左右比較を共用します。連続認識のBEFOREはライブ、AFTERは解析フレームです。同時点の厳密比較には静止画を使用します。認識OFF・カメラ停止・モード退出でWorkerと一時画像を解放します。設定と画像を含まない実験記録は維持します。

OCR結果・コード内容・ファイル名・登録画像・合成文字は自動保存しません。手動の実験記録とJSON／CSVも種類・件数・形式・特徴点数などの許可済みメタデータだけです。明示保存した登録画像と、利用者が保存したマーカーPNGは別です。[対応形式](docs/TEXT_MARKER_FORMATS.md)、[設計・調査・制約](docs/V0_6_0.md)、[ライセンス](THIRD_PARTY_NOTICES.md)を参照してください。

### 複合認識（v0.5.0）

1. 下部の「認識モード」→「複合認識」を選択します。初期設定は静止画です。「端末内画像」またはカメラ起動後の「カメラから1フレーム取得」で1回解析します。同じ画像で実験を変更すると順番に再解析できます。画像はタブ内メモリだけに保持します。
2. 「実験」で物体＋色、色＋動体、複数物体、物体＋動体、人物＋物体、時系列認識、物体＋風景を選びます。物体＋風景は静止画専用です。風景モデル・内部解像度は既存の風景モード設定を引き継ぎ、原本・v0.4の内部サイズ調整内容は変更していません。
3. 色を調べる場合は元映像の対象位置をタップします。詳細設定でHSV許容幅、動体感度、最小領域を調整します。「物体＋色」では枠内の主要3色と指定色割合を表示します。「色＋動体」は指定色領域を追跡し、その中の背景差分と軌跡・方向・正規化速度を表示します。
4. 動体・追跡・時系列の実験は「入力」を連続認識にして、カメラを固定してください。単発静止画から速度・接近／離反・移動開始／停止・対象出現／消失は判定しません。静止画でも指定色・重なりの成立は記録できます。
5. 「複合認識の調整・表示」で長辺160/320/480px、完了後待機200/500/1000/2000ms、自動／手動、撮影からの有効期限1〜15秒、信頼度・割合・距離・速度の閾値、継続時間、ヒステリシスを調整します。描画要素だけの変更とBEFORE/AFTER比較は推論を再初期化しません。「追跡・背景基準をリセット」「複合設定を初期値へ」も利用できます。
6. 「複合認識の結果・性能・イベント」で座標、関係、使用エンジン、各推論時間、統合時間、平均／最大処理時間、更新時刻、イベント根拠を確認します。「実験記録」でメタデータを最大50件保存し、JSON/CSVで書き出します。イベント履歴は直近100件、静止画を再解析すると履歴を初期化します。画像・マスク・ファイル名は保存しません。

距離・速度は**元画像幅／高さに対して各軸を0〜1にした2次元座標**の値です。物理距離、接触、把持、因果関係を示しません。人物は分割マスク全体との位置関係で、手指のランドマークや個人別追跡は使用しません。連続表示のBEFOREはライブ、AFTERは解析時点の画像です。同じフレームの厳密比較には静止画を使ってください。詳細は [v0.5.0設計・制約・検証](docs/V0_5_0.md)を参照してください。

### 共通操作

1. 下部の「カメラを起動」を押してカメラの使用を許可します。
2. 下部の「認識モード」で物体認識・色認識・動体検出・輪郭／図形認識・領域認識・風景認識を選びます。カメラを再起動せずに切り替えます。物体認識はモデル読込後、位置・日本語名・信頼度を表示します。未登録名は英語のまま、最大20件です。
3. 「前面に切替／背面に切替」でカメラを切り替えます。前面映像と認識枠は鏡像表示です。端末が指定方向を提供しない場合はブラウザが選んだカメラとなります。診断のカメラ設定で確認できます。
4. 「認識 ON／OFF」は認識のみを切り替えます。OFF中も映像を表示します。
5. 「詳細設定」で信頼度（10〜95%）、解析長辺（320/480/640px）、推論完了後の待機時間（100/200/500ms）を変更できます。
6. 「カメラを停止」で全Track、Worker、モデルを解放します。画面のバックグラウンド移行でも停止します。復帰後は手動で再起動します。
7. エラー時は案内に従い「認識を再試行」または「カメラを再試行」を押します。認識エラーではカメラを止めません。モデル取得失敗時はモデル・WASMの配置を確認するか、モデル不要の別モードへ切り替えてください。

### 風景認識（v0.4.0）

静止画からの実験が初期設定です。カメラの許可なしでも使えます。

1. 下部で「風景認識」を選び、「端末内画像」からPNG/JPEG/WebPなどを読み込みます（20MBまで）。元画像を長辺1024px以下に縮小してタブ内メモリに保持し、自動で1回解析します。カメラを起動した場合は「カメラから1フレーム取得」でも同じ実験ができます。
2. 「表示・加工」で元映像、色分けマスク、半透明マスク、選択カテゴリ強調を選びます。映像をタップするとその位置の推定カテゴリを表示・選択します。凡例と折りたたみの一覧でカテゴリごとの占有率を確認できます。BEFORE/AFTER/左右比較も使えます。
3. 色変更（明暗を保持）、対象だけ／対象以外をモノクロ、明度変更、単色化を選択できます。選択カテゴリのピクセルだけが対象です。分類誤りもそのまま加工されるため、必ずマスクと比較してください。モデルからピクセルごとの信頼度は取得していません。
4. ADE20Kは背景を含む151出力で室内・屋外、Cityscapesは19出力で道路周辺です。モデルを切り替えても同じ静止画を保持し、旧モデルを解放してから順番に解析します。Cityscapesの床・天井・家具は未対応と表示します。[全カテゴリ一覧](docs/SCENE_CATEGORIES.md)を参照。
5. 各モデルの解析後に「実験記録」で記録してください。同じ画像には同じ比較用IDが付くため、JSON/CSVでモデル名・占有率・容量・読込／推論時間・解析／内部解像度を比較できます。画像そのものやファイル名は記録しません。室内／屋外は詳細設定で記録用に指定し、自動判定はしていません。
6. 連続実験ではカメラを起動して「入力」を「カメラ連続認識」に変更します。初期基準は推論完了後2秒待機。詳細設定で長辺160/257/384px、待機1/2/5/10秒、自動／手動を選べます。自動はv0.3.1と同じ実測移動平均方式で最大15秒まで待機を広げます。30 FPSを狙うモードではありません。遅い場合は静止画・160pxへ戻してください。
7. 「画像を解放」「モデルを解放」で明示的に解放できます。カメラ停止、別モードへの移行、ページ終了では風景の画像・マスク・モデルも解放します。画像は再読込やモード移行後に復元しません。設定と画像を含まない実験記録だけを保存します。

モデル原本とWASMは同じサイトから配信します。TensorFlow.js 4.22.0、Worker/WASMを優先し、必要時はWebGL／CPU、Workerなしの互換方式へ切り替えます。**実験用内部サイズ版**として非学習サイズ定数とプーリングだけをメモリ内で調整し、内部サイズを161/257/385の正方形にします。学習済みフィルタ・配布原本は維持しますが、標準サイズでの精度とは異なります。小領域や境界の精度を保証しません。[モデルの選定・配布条件](docs/SCENE_MODELS.md)を確認してください。

静止画のBEFORE/AFTERは同じ画像を使います。連続認識はBEFOREがライブ映像、AFTERが解析時点のフレームで、時間差があります。古いマスクは撮影時点から15秒で失効します。認識FPSは実際の完了通知の間隔で、静止画の手動操作待ちも含み、2回未満は「—」です。Tensor管理量は端末全体のメモリ使用量ではありません。

### 人物・部位の領域認識（v0.3.0〜0.3.1）

認識モードで「領域認識」を選び、映像の下にある「実験」から選択します。人物／背景加工には軽量な二値モデル、部位／部分加工には6カテゴリモデルを必要時だけ読み込みます。同じモデルを使う実験や表示・加工設定の変更では再読み込みしません。

- **人物**: 元映像、人物領域の強調、人物だけ、背景だけ、白黒の人物マスク。切り抜いた側以外は黒です。「詳細設定」の境界の滑らかさ・補正で、確率の閾値付近と空間的な境界を平滑化します。
- **部位**: 背景・髪・体の肌・顔の肌・服・その他を色分けし、「部位の検出状態・占有率」に部位名、検出状態、占有率、使用モデルを表示します。0.1%未満は未検出扱いです。二値モデルの髪・服等、6カテゴリモデルの目・口・個々の指などは未対応と明示します。
- **背景加工**: ぼかし、単色、端末内の画像、減光。ぼかし強度と境界補正を調整できます。背景画像はファイル選択で読み込み、長辺960pxまで縮小してこのタブのメモリにだけ保持します。15MBまで、PNG/JPEG/WebP等、ブラウザでデコード可能な画像を使用してください。送信・外部ストレージ保存は行いません。「背景画像を解放」でメモリから外せます。画像は再読込すると失われます。
- **部分加工**: 髪・服の色変更は元画素の輝度を使って明暗・質感を残す近似です。任意の対応カテゴリに対して「対象だけモノクロ」「対象以外をモノクロ」も選べます。対象が0.1%未満・モデル未対応なら元映像を維持し、理由を表示します。髪型・衣服の材質そのものは生成しません。

領域認識のBEFOREはライブ映像、AFTERは直近のマスクとライブ映像から最大15 FPSで合成します。描画FPSは画面の描画回数で、加工映像の更新回数や認識FPSとは異なります。左右比較は同じcontain座標と鏡像変換を使います。加工は最短約67ms間隔で更新し、負荷によってさらに遅れるため、同時刻の画素比較ではありません。マスクが期限切れの間はAFTERも元映像へ戻します。

#### 使用モデル・対応カテゴリ・ライセンス

MediaPipe Tasks Vision **0.10.21**のImage Segmenter、`VIDEO`モード、**CPU** delegateを使用します。classic Workerが使えない場合はメインスレッドCPUへ切り替えます。GPUのカテゴリ出力には[iOS Safariでの不整合報告](https://github.com/google-ai-edge/mediapipe/issues/6142)があるため、v0.3.0ではGPUを選択しません。

| モデル | 固定版・内部入力 | 正確な対応カテゴリ | 実ファイル容量 | ライセンス |
| --- | --- | --- | --- | --- |
| SelfieSegmenter (square) | float16 / revision 1 / 256×256 | 背景、人物 | 249,537 bytes（約0.24 MiB） | Apache-2.0 |
| SelfieMulticlass 256×256 | float32 / revision 1 / 256×256 | 背景、髪、体の肌、顔の肌、服、その他（装飾品等） | 16,371,837 bytes（約15.61 MiB） | Apache-2.0 |

出典は[公式ガイド](https://ai.google.dev/edge/mediapipe/solutions/vision/image_segmenter)、[人物モデルカード](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20MediaPipe%20Selfie%20Segmentation.pdf)、[部位モデルカード](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20Multiclass%20Segmentation.pdf)です。`npm run assets` が固定URLから `public/models/` に配置し、配布URL・SHA-256・容量・カテゴリを `public/assets-manifest.json` に記録します。`npm run build` はハッシュ検証後、モデルと既存WASMのSIMD/非SIMD両方を `dist/` へコピーします。Apache-2.0本文と帰属情報も同梱します。

「領域認識の性能」でロード・初期化時間、直近最大120回の平均／最大推論時間、推論FPS、画像サイズ、推論間隔、加工時間を確認できます。長辺160/256/384pxは渡す映像と加工のサイズです。モデル内部入力は256×256で固定なので、解像度を下げてもモデル自体の演算量が比例して減るわけではありません。詳細設定の負荷調整は初期値「自動」。実測処理時間の移動平均から、選択した基準間隔以上・最大2000msで完了後の待機を調整し、解像度は変更しません。基準の初期値は200ms。手動では100/200/500/1000msで固定します。キューは蓄積せず、次の直近フレームだけを扱います。「負荷・品質設定を初期値に戻す」で復元できます。高負荷表示は処理時間に基づき、CPU使用率・電池消費量は表示しません。

平滑化のON/OFFと時系列補正強度、従来の境界補正を調整できます。小さな信頼度変動を平滑化し、孤立ノイズを除去します。画素の色やカテゴリが大きく変化した領域は古い確率を混ぜず、モデル・解像度変更や期限切れでも履歴を消します。マスク期限は撮影時点から初期値2000ms、500/1000/2000/5000msで調整可能です。高速な移動や低頻度推論の追従には制約があります。

「実験記録」で現在の日時、認識モード、モデル、解析解像度、FPS、平均／最大推論時間、待機間隔、実行方式、UA・言語・platform・論理コア数をブラウザ内に記録できます。最大50件、超過時は最古から削除。最新10件を残す・全削除・JSON/CSV書出しに対応します。`camera-vision-lab.experiments.v1` にメタデータだけを保存し、画像・映像・背景画像名は保存しません。保存拒否・容量不足時はタブ内で保持し、書き出せます。

領域認識の設定は `camera-vision-lab.segmentation.v1` に保存します。既存の `camera-vision-lab.v2` にあるHSV許容幅・感度・比較表示などは保持します。画像ファイルやフレームはlocalStorageに書きません。詳細なPC測定・制約は [v0.3.0検証記録](docs/V0_3_0.md)を参照してください。

### 新しい3モードと比較表示

- **色認識**: 映像をタップすると3×3画素の平均色をHSVへ変換して追跡します。色相（初期±22°）、彩度・明るさ（各初期±35%）の許容幅を詳細設定で調整します。同色の複数領域を強調し、ID・中心・面積・軌跡を表示します。灰色付近は色相を判定しません。
- **動体検出**: カメラを固定して「背景基準を再取得」を押します。背景との差を領域化してID・移動方向の矢印・表示px/s・軌跡を表示し、重心の変化が2解析px未満の状態が約1.2秒続くと静止とします。カメラ移動や照明変化も検出されます。基準に写っていた物体の元の場所も差分として残るため、必要に応じて背景を再取得してください。
- **輪郭・図形認識**: RGB各成分の平滑化・Sobelエッジから連結した輪郭を抽出し、直線・円形・三角形・四角形・未分類の輪郭を表示します。中心・面積・傾きは「検出データ」で確認できます。円形には一意の傾きがないため「—」です。図形は高コントラストで分離したものを対象にします。
- **比較表示**: 通常＝映像＋認識結果、BEFORE＝元映像、AFTER＝黒背景の認識結果、左右比較＝左BEFORE／右AFTER。表示を切り替えても認識を再初期化しません。左右とも画像全体を余白付きで収め、同じ座標変換を使用します。画像処理結果は非同期解析した直近フレームなので、移動中はライブ映像との時間差があります。

新モードは長辺320pxまでに抑え、最大24領域を処理します。「検出データ」の中心・面積は元映像の左上を原点とする**解析画像座標／解析px²**です。図形の面積と中心は凸包による近似で、凹形の実面積ではありません。直線は長さ18px以上を対象とし、面積は「—」です。速度は比較表示や画面幅に応じた**表示上のpx/s**で、m/sではありません。方向は右0°・下90°、前面の鏡像も反映します。

設定は `camera-vision-lab.v2` キーのlocalStorageへ保存します。モード、追跡色・HSV許容幅、動体・輪郭感度、最小面積、比較表示を保存します。フレーム・背景画像は保存せず、背景・追跡履歴は処理中のメモリだけに保持します。保存不可の場合も画面操作を継続できます。

映像FPSは `requestVideoFrameCallback` の映像フレーム通知、描画FPSは実際のCanvas描画、認識FPSは処理完了回数を別々に計測します。映像・描画は直近2秒、認識は低頻度推論に対応する直近10秒の通知間隔から算出し、2サンプル未満は「—」です。映像API非対応環境も「—」です。処理msはMediaPipe推論または画素処理アルゴリズムの直近呼出時間で、画像取得・転送・描画・待機は含みません。数字は実測値のみです。通常の認識枠は2秒、領域マスクは設定された期限で失効します。

## 構成と採用理由

Vite + TypeScriptを採用。静的ファイルへビルドでき、型を持つ共通インターフェースと依存固定を簡潔に管理できます。UIフレームワークは追加していません。

- `src/core.ts`: カメラのライフサイクル、結果変換、座標変換、エラー、計測
- `src/modes/types.ts`: モード共通インターフェース
- `src/modes/object-detector.ts`: Worker優先／CPU互換方式と解放
- `public/vision-worker.js`: classic Worker上の直列推論
- `src/main.ts`: UI、描画ループ、単一推論ループ
- `src/settings.ts`, `src/display.ts`, `src/render.ts`: 設定保存、表示とタップ座標、比較描画
- `src/modes/session.ts`: カメラと独立したモードの直列初期化・解放
- `src/modes/pixels.ts`, `image-processing.ts`, `processing-worker.ts`: 自作画素処理とWorker／CPU互換方式。追加ライブラリ・AIモデルなし
- `public/models`, `public/vendor`: 固定モデルとJS/WASM実行アセット
- `public/assets-manifest.json`: 配布元、バージョン、サイズ、SHA-256
- `scripts/prepare-assets.mjs`: アセット準備・ハッシュ検証
- `tests/`: 変更に直接関連する単体・ブラウザテスト

WorkerとImageBitmap/OffscreenCanvasを優先します。非対応・初期化失敗・Worker推論失敗時はCPUによるメインスレッド推論へ切り替えます。互換方式は同期APIのためUIが一時的に止まることがあります。WASMのSIMD選択はMediaPipe Resolverが行い、両方のWASMを同梱します。最初の推論が完了するまで互換性は確定しません。

## プライバシーと配布

物体・領域認識が同じサイトへのGETでモデル・WASMを取得します。色・動体・輪郭の3モードは専用WorkerのJSのみを使い、モデル・WASMを読み込みません。カメラ映像の送信・永続保存、解析・広告・遠隔推論SDKはありません。CSPで接続先を同一オリジンに制限します。背景ファイルのデコード用に画像のblob URLだけを許可しています。ビルド時のnpmとアセット取得にはインターネット接続が必要です。実行時に外部CDNへアクセスしません。サービスワーカーは導入しておらず、オフライン初回起動は保証しません。

`npm run build` の `dist/` が静的配布物です。相対baseによりGitHub Pagesのサブディレクトリ配置を想定しています。モデル・WASM・licensesを含めて配布します。親リポジトリを静的公開する構成のため、`dist/` もGit管理対象とします。公開に反映する際はソースと一緒にビルド済みファイルをcommit・pushする必要があります。この作業ではpush・公開を行っていません。

ソースは「iPhoneセンサー実験室/カメラ認識実験室」直下に配置しています。親の実験メニューは `カメラ認識実験室/dist/` を開きます。変更後はこのフォルダで `npm run build` を実行してから親メニューで確認してください。親フォルダの `node server.js` でPCから確認する場合は `http://localhost:8123/` を開きます。iPhoneのカメラ利用にはHTTPS配信が必要です。

ビルドの最後に、静的HTMLの参照、モデル・WASMのハッシュ、配布物のGit除外設定を確認します。配布物がGit管理対象外だとビルドを失敗させ、ローカルでだけ開ける状態を検出します。既存ビルドだけを確認する場合は `npm run check:static` を実行します。

親メニューとGitHub Pages形式のサブパスを確認する場合は、ビルド後に `npm run test:menu` を実行します。PCのChromeでGit配布対象の静的ファイルだけを使い、メニュー遷移から物体モデル・画像処理Workerまで確認します。push・公開は行いません。
