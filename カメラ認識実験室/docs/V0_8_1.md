# v0.8.1 — PHOTO HIDE & SEEK

「奥行き認識」内の「D. かくれんぼ」。写真の中にロボットを隠す→写真を隠して端末を渡す→相手が探す→発見→同じ写真で隠し直す、小さなローカル実験です。

## 調査と再利用

既存のScenePanelによるファイル／撮影フレーム入力、1024px上限の元画像座標、DepthModeのWorker／単一スレッドWASM、明示解析・世代管理・ModeSession、DepthPanelの生深度による遮蔽と前面反転、VisionRendererの静止画描画を再利用しました。モデル・Worker・重み・推論前処理には変更を加えていません。新しい認識ライブラリもありません。

解析済み写真を選択中なら、そのままかくれんぼへ移行できます。未解析の写真だけ既存の「奥行きを解析」を押します。かくれんぼ内では解析済みのボタンを無効にし、ロボットの移動・奥行き変更・隠し直しで再推論しません。解像度変更や画像差替えは既存の結果無効化に従います。

## 可視性と発見の仕様

- 既存のロボットCanvas素材から透明背景を除去して使用。かくれんぼではアンテナ装飾も描画・集計・正解範囲から外し、本体だけを扱います。元の自由配置やARカードの素材・処理は変更しません。
- 遮蔽前の本体alphaが128以上の画素を分母に、既存の`occlusionAlpha`で残った同じ画素を分子にします。写真と生深度は同じ元画像座標です。色分け画像を判定には使いません。
- 可視率12%未満は「隠れすぎ」、65%超は「見えすぎ」で開始不可。12〜65%は「ちょうどいい」。加えて可視部分の最大4近傍連結成分が画面上36 CSS px²以上、幅・高さが各6 CSS px以上必要です。点状ノイズや細すぎる断片だけでは開始できません。これは可視性の初期基準で、実機の指操作で調整余地があります。
- ロボットを置く矩形全体が写真内に収まることも必要です。画像外へ隠す配置は可視率にかかわらず拒否します。編集時は理由と割合を表示し、画面上でも見える部分を確認するよう案内します。
- 探索では、遮蔽後の本体画素とその周囲7 CSS pxの円形許容範囲だけを正解にします。隠れた胴体・透明余白・元矩形全体は正解にしません。既存の反転座標変換を通します。
- 発見後は650msで遮蔽画素をフェード表示。描画だけの演出で、推論回数を増やしません。停止・モード変更・画像破棄で演出をキャンセルします。

## 渡す・探す画面

状態はedit / pass / search / foundの4つ。passは元映像・結果の両方を塗りつぶしたフレームに差替え、写真を隠して「端末を渡してください」「探し始める」を表示します。探索では編集、奥行き・色分け・診断、記録、ファイル入力、モード選択、比較UI、可視率を隠します。通常の比較設定は保存したまま、かくれんぼ内の描画・タップは1枚の通常表示に揃え、BEFORE側への漏れや座標ずれを防ぎます。終了すると従来の比較設定へ戻ります。

ヒントは押したときだけ写真の上／中央／下・左／中央／右の大まかな区画を表示します。前面反転も反映します。位置、写真、深度マップはセッション内だけで、localStorageや実験記録へ追加しません。リロードでプレイを復元しません。タイマー・得点・共有はありません。

写真の表示は幅を優先し、かくれんぼでは写真の縦横比で表示枠を調整します。スクロールを止める`touch-action:none`は編集時のCanvas操作領域だけです。探索中は不要なドラッグ操作を受け付けません。

## 配布サンプルと実モデルの確認

`public/samples/coffee.png`はRachel Michetti撮影のコーヒーカップ、皿、スプーン、木のテーブルの実写真です。前面の不透明なカップと、その後ろ／下にある皿・テーブルの推定境界で部分遮蔽を試せます。scikit-image v0.25.2から取得し、[公式の写真別CC0表記](https://scikit-image.org/docs/0.25.x/api/skimage.data.html#skimage.data.coffee)を確認しました。600×400、466,706 bytes、無改変。取得先とSHA-256は同梱の`coffee-LICENSE.txt`に記載。静的配布チェックでPNGのハッシュと許諾表示を検証します。必要時だけ同一サイトから画像を読み込みます。

既存Depth Anything V2 Small Q4 ONNX（Apache-2.0、27,404,416 bytes）とONNX Runtime Web 1.23.2（MIT）をそのまま使用。モデルの固定revision・SHA・前処理・出力方向は[V0_8_0.md](V0_8_0.md)のままです。実写真を実Worker／WASMで解析し、写真内の正規化位置(0.30, 0.60)、奥行きスライダー34で本体の約61%が残り、カップの輪郭に沿う部分遮蔽を目視確認しました。この配置は開発時の再現目安で、自動的に答えを置く機能ではありません。

PC Windows Chrome 157、モデル入力280×182・元写真600×400の試行では、モデル読込・初期化1394.3ms、今回解析569.2ms。単発実測でキャッシュや環境により変動します。iPhoneの性能値ではありません。数値・UA・公開サンプルに対する開発用配置情報だけを`depth-validation/hide-sample.json`へ記録し、写真や生マップはログに含めません。

## 未確認・制約

サンプルでの成功と利用者自身の写真での成功は別です。写真によって推定境界は不正確で、特に透明・反射・細い物体・絵画は期待どおりに隠れない場合があります。単眼の相対深度であり、実距離ではありません。

指定された「手前の不透明なコップ・中央の箱・奥の壁」と、コップと箱の前後を交換した実写真は手元にありません（利用者も写真なしと回答済み）。実物を撮影できる環境を用意できていないため、この2枚の比較は未確認です。配布サンプルや模擬マップで代替したとは報告しません。

iPhone Safari実機の指操作・画面サイズ・実カメラ／前面反転・EXIF／HEIC・メモリ・性能は未確認。[実機手順](IPHONE_CHECKLIST.md)でサンプル、自身の写真、指定写真ペアを分けて確認します。利用者画像・OCR内容・深度マップの送信／自動保存、commit・push・公開は行いません。

次の改善候補は実機のタップしやすさに応じた可視性基準の調整、境界ノイズの軽減、写真別の失敗例整理です。
