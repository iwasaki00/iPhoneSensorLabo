# v1.0.0 — CAMERA APPLICATION DEMOS

## 入口と共通動作

親メニューの既存リンク→カメラ認識実験室→「応用デモ」。既存画面には入口ボタン1つだけを追加し、従来の初期モード・認識画面を維持する。専用の静的ページ`demos.html`に番号付き6本を置いた。

各デモに短い目的、現在やることの1行案内、具体名のボタン、いつでも開ける「詳しい使い方」、サンプル、やり直す、応用デモに戻るを用意。詳しい使い方は、目的・準備・番号付き手順・成功時の表示・具体的な対処と限界を含む。iPhone縦390 CSS pxを基本に、画像は最大65svh。通常のページスクロールを維持し、範囲・本体・場所を指定するCanvasだけでタッチスクロールと選択を抑える。

カメラは明示操作だけで起動し、既存`Camera`クラスを再利用。デモ終了・やり直し・停止・ページ退出・バックグラウンド移行でTrackを停止する。Workerと推論の所有者をデモ単位に限定し、世代番号で遅い結果を破棄する。サンプル映像の表示はrAF、解析は完了後の待機で分離し、`AdaptiveLoad`を再利用する。解析要求を積み重ねない。重いモデル・言語データは必要なデモだけで同一サイトから遅延取得する。

入力画像は長辺960px以下、画像差分は長辺320px以下。写真・前後画像・OCR内容・ROI・結果はセッションのメモリだけ。localStorage／履歴／JSONへの自動保存、外部AI送信、分析SDK、商品照会APIを追加していない。メモのコピーだけ利用者の明示操作で実行する。

## 再利用したエンジン・判定

### ① 物体＋手動本体位置

既存`ObjectMode`／MediaPipe Tasks Vision 0.10.21／EfficientDet-Lite0を使用。cupカテゴリ、信頼度0.25以上のみを対象とする。複数なら最大のカップを使う。箱は利用者のタップだけで登録し、自動認識しない。

写真のx・yを各辺で正規化し、カップ中心と本体中心の距離を使う。0.34超を一度検出してから、0.24未満が異なる解析フレームで2回続くと1回発火。検出なしで連続回数をリセットし、起動後は再発火しない。再体験はやり直す。描画フレームを検出回数には数えない。推論に2.5秒超かかった結果は採用しない。モデルの起動中はサンプル再生を待つ。

### ②⑤ 共通画像比較

前後のRGB各画素の最大チャンネル差を輝度画像にし、既存`PixelProcessor('motion')`の閾値・ノイズ除去・連結領域を通す。差分閾値は約27、最小30画素。②は小さすぎる領域を除き、全体の変化0.1%未満や35%超なら撮り直し案内。移動前後の両領域を残す。探すときのタップは差分枠と画面約7pxの許容範囲で判定する。

⑤は登録した1〜3枠だけの差分画素率を確認し、6%超を要確認とする。変化なしの画面も正当な結果。全体が35%超変わる場合は撮り直し。異なる解像度は同じ縦横比ならそろえるが、縦横比が違う写真は拒否し、画像位置合わせや手持ち補正は行わない。

ブラウザ`ImageData`のwidth／heightは列挙可能なプロパティではないため、オブジェクトのspreadで欠落する問題を実ブラウザテストで発見し、寸法を明示して渡すよう修正した。単体テストでも非列挙アクセサを追加して確認している。

### ③ 同じ領域での色と動き

色・図形・動体の`ImageProcessingMode`をそのまま使う。赤はHSV色抽出、丸は既存円形分類、青は同じ入力フレームを色と動体へ順番に渡す。青マスクと動体マスクの画素積を取り、青領域内で30画素か面積の12%の大きい方以上が重なったときだけ達成。横で別物が動くだけのケースを除外する。最初の達成領域で終了する。

### ④ 風景と加工

既存DeepLab v3 ADE20K／MobileNet-v2、revision 1、uint8重み、2,438,371 bytes、Apache-2.0。TF.js 4.22.0。`SceneMode`のWorkerとWASM→WebGL→CPUの既存互換経路を維持。既存の非学習サイズ定数・プーリング調整257×257もそのまま使い、学習済み重みやモデル原本には変更を加えていない。[モデル識別と内部調整](SCENE_MODELS.md)。

開発時、同じ道路サンプルでCityscapesは空を分類したが道路を必要量分類できなかった。既存ADE20Kで両カテゴリを分類できたため本デモではADE20Kを採用。写真ごとの特別座標や代替マスクはない。既存の風景実験画面のCityscapes比較機能も維持する。

夜の空は空カテゴリへ青の明暗維持tint＋明度45%、溶岩の道は道路カテゴリへ赤橙tint。大がかりな炎・溶岩アニメーションではない。0.2%未満の対象は対象なし案内。加工には既存`sceneComposite`を使い、元画像とカテゴリマスクを保持する。推論完了後にモデルを解放し、切替で再ロードしない。

ロボットを動かす場合は`index.html?demo-depth=1`から既存の奥行き認識／自由配置へ移動する。同じ同梱道路サンプルを読み込むが、深度は利用者が解析ボタンを押した時だけ実行する。利用者自身の画像のページ間転送・永続保存は追加せず、再選択を案内する。

### ⑥ OCR

既存`TextMarkerMode`／Tesseract.js 7.0.0／Tesseract Core・言語データを再利用。英語または日英混在を必要時に同一サイトから取得。2つのROIを順番にWorkerで読み、各Workerを解放。元画像の切り取りと生のOCR文字列を並べ、編集可能にする。符号・小数点・単位の正規化・数値化はしない。低信頼は空欄、再指定と手入力を可能にし、人が確認したチェック後にのみコピーする。

## PCの確認・実測

Windows、Chrome 157、390×844 CSS px。2026-11-15 JST。各1回の実行例で、iPhoneの性能ではない。

- ①の最終解析162.5ms、実測解析FPS 2.13。読込時間を含む起動全体のベンチマークではない。[記録](demo-validation/workshop.json)／[起動画像](demo-validation/workshop.png)。
- ④のモデル読込419.0ms、推論2543.1ms、空70.4%・道路11.2%。効果切替の推論回数は増えない。[記録](demo-validation/world.json)／[溶岩色の加工画像](demo-validation/world.png)。
- ⑥の2範囲の読込・前処理・認識は910.0ms／598.4ms。各処理には言語データの必要時読込が含まれ、純粋な推論時間ではない。[記録](demo-validation/ocr.json)。公開した記録は架空サンプルの成功フラグと計測だけで、利用者のOCR内容を記録する機能ではない。

単体テストは共通比較・移動前後・変化なし／全体変化・座標ヒット・同一画素の青＋動き・起動の一回発火を対象とする。ブラウザテストは6本のサンプル、ファイル入力、確認付きコピー、やり直し、デモからの退出、推論中の世代破棄、模擬カメラの停止、外部要求なしに絞る。全件回帰試験は行わない。

最終結果は、関連単体11件、Chromeの応用デモ8件と既存のかくれんぼ／ARカードシミュレーター2件、Edgeの関連5件が成功。Edgeは②・③・⑤・ファイル入力／模擬カメラ停止・初期化中の退出を確認し、①④⑥の実モデル推論は今回Chromeで確認した。推論中退出の制御試験だけは遅延する模擬Workerを使い、実モデルの認識試験とは区別する。

`npm run build`と静的配布検証が成功。既存固定48資産に加えサンプル9資産の容量／SHA-256を検証し、distへ反映。既存の大きいTensorFlow.js chunk警告は残る。親メニュー専用確認はGit管理対象となる110静的ファイルを一時配信し、親メニュー→v1.0.0→6本一覧→②のサンプル結果→既存アプリへの復帰まで成功。HTTP／ページエラー・外部要求・カメラ起動なし。管理対象テキストのCRLFは0件で、`git diff --check`も成功。既存ARカードテストが再生成した過去版の画像は変更対象に含めず復元した。

## 起動・検証コマンドと未確認事項

`npm run dev`で既存アプリ、`/demos.html`で応用デモ。`npm run build`でdistへ反映。関連単体は `node --experimental-strip-types --test tests/demos.test.ts tests/core.test.ts`、ブラウザは空きポートを指定して `npx playwright test tests/browser/demos.spec.ts`。親メニュー経由は `npm run test:menu -- --demos-only`。

iPhone Safari実機、実カメラの精度・MP4再生・指操作・クリップボード・日本語実写真OCRは未確認。[iPhone手順](IPHONE_CHECKLIST.md)に各デモを個別に記載。カメラ揺れ、影、照明変化、薄い色、小さな輪郭、誤分類・OCR誤読が主な制約。完成品のゲームや業務点検ではなく、一通りの入出力を確認する簡易デモとして扱う。commit・push・公開は行わない。
