# モード追加方針

v0.7.0のARカード実験は文字・マーカー内の`cards`サブモードです。Workerには既存`marker`処理を要求し、`cards.ts`の対応表・純粋なペア状態管理へ同一フレームの結果を渡します。判定はTextPanel.updateから1検出につき1回だけ行い、CardView.animate／renderでは更新しないでください。近接／離隔のヒステリシス、重複フレーム拒否、TTL拒否、欠落でロックを解除しない仕様を維持します。期限切れは`clear(true)`でペアのロックを残し、停止・モード変更の通常clearでは履歴ごと解除します。自作図形を小さなテクスチャへ描画し、既存のprojection.tsで四隅へ合成します。対応カードとペア追加はマーカー辞書を変えず、未登録IDを合成しない方式で拡張してください。

v0.6.0のTextMarkerModeは共通RecognitionModeとスケジューラーへ接続し、classic broker Worker内で必要なエンジンだけを読み込みます。OCRは子Worker、コード・ORB・マーカーはbrokerで処理します。開始ハンドシェイク、dispose応答、子Worker解放、タイムアウトを維持してください。結果は共通EngineResultの正規化座標・frameId・撮影／処理／期限を使い、OCRのROI・回転を逆変換してから表示します。TextEntityの任意拡張項目を他モードで必須にしないでください。TextPanelが所有する画像とCanvasはモード退出・停止で解放し、比較表示を再利用します。

文字列・コード内容・画像は実験記録に渡さず、`textmarker/record.ts` の許可リストに従って集計値だけを保存します。永続画像保存と外部URLを開く操作には明示ボタンを使います。依存は固定版・同一サイト配信・ハッシュ検証・許諾文同梱で追加し、既存モードの起動に不要なWASM／辞書を読み込まないでください。[v0.6設計](V0_6_0.md)を参照。

v0.5.0の `MultiMode` は既存モードを必要時だけ生成し、所有Canvasの同じ画像を順番に入力します。既存のRecognitionMode実装を複合側へ複製しないでください。結果は `multi/fusion.ts` のEngineResultへ変換し、フレームID・撮影時刻の一致とTTLを検査してから統合します。時系列の異なるフレームを比較する処理はFusionHistoryへ隔離します。座標・面積・距離は元画像基準に正規化し、表示変換をエンジン内へ持ち込まないでください。取得できない信頼度・距離は省略します。

新しい組み合わせは `multi/settings.ts` の実験定義とMultiModeの逐次処理へ追加します。人物・風景のような重いモデルは同時保持を避けます。静止画の入力はScenePanelの既存機能と `inputOverride` を共有し、風景モードの設定を書き換えないでください。描画要素の切替はpresentationだけで処理します。記録の拡張には `multi/record.ts` の容量制限付きメタデータ許可リストを使い、マスクや画像を渡さないでください。[詳細設計](V0_5_0.md)を参照。

`RecognitionMode` の `id`、`runtime`、`initialize()`、`infer()`、`dispose()` を実装し、モード固有の依存を `src/modes/` に閉じ込めます。v0.2.0では従来の `detections` に加え、`regions`（中心・面積・傾き・多角形・追跡情報）、`mask`、解析サイズ、処理時間を共通結果に追加しました。`configure()` は設定変更、`reset()` は背景などの履歴再取得に使用します。

v0.3.0は `segmentation` 結果にカテゴリマスク・人物信頼度・同じ時刻の元フレームを追加しました。`src/segmentation/` が設定・モデル定義・画素合成・UIを担当します。サブモードから必要なモデルを決め、モデルが同じなら合成設定だけを変更します。設定は旧v2キーと分離し、モデルごとの実ラベルだけを使います。マスクはTasksの返すリソースから配列にコピーしてから `close()` し、WorkerのImageBitmapも毎回解放します。

モードの切替は「スケジューラー停止→世代ID更新→進行中結果を無視→旧モードdispose→初期化キューで旧処理の終了を待機→新モードinitialize→再開」の順で行います。`ModeSession` が初期化を直列化し、`inFlight` が解析の多重起動を防ぎます。カメラの世代IDはモード切替では更新せず、MediaStreamを維持します。Workerは終了で解放し、メインスレッドのTasksはclose、画像処理の背景・追跡配列はresetします。認識OFFでもモードを解放します。非同期のTasks初期化自体は即時キャンセルできない場合があり、その終了を待って次へ移行します。

AIモードにはモデル・ライブラリの固定バージョン、ライセンス、同一サイト配信パス、SHA-256、互換方式を用意します。通常画像処理モードは専用Workerにアルゴリズムを追加し、Worker非対応時はメインスレッドで実行します。不要なライブラリやモデルは初期化しません。処理完了後に次の予約を入れ、映像フレーム・Canvas描画・認識完了を別々に計測します。

比較表示は `VisionRenderer` と `displayPanes` の責務です。モードの再初期化と分離し、元映像のcontain領域を基準に解析結果を正規化して描画します。前面鏡像は描画とタップ逆変換の両方に適用します。姿勢のランドマークなど別形式を追加する場合は、結果の識別子付きunionと描画アダプターを追加してください。

v0.3.1は既存の世代ID・初期化キュー・inFlightを再利用します。解析解像度変更でも結果世代を更新し、進行中の古いサイズの結果を破棄します。自動負荷調整とマスク履歴は `segmentation/stability.ts` に分離し、モデル切替・停止でリセットします。MaskHistoryはTasksのリソースを保持せず、所有配列だけを扱います。SegmentPanelが推論とは独立した最大15 FPSのライブ加工を担当し、RendererがBEFOREのライブ表示と位置変換を担当します。描画失敗は認識エラーとして処理し、映像へ復帰します。

新エンジンも完了後スケジューラーを使い、未処理フレームをキューにしないでください。結果の寿命は撮影タイムスタンプから判断し、Worker転送前に必要なマスクをコピーしてネイティブ結果を閉じます。`experiments.ts` は許可したメタデータだけを記録・書出しします。新結果にフレームや画像参照が増えても記録スキーマへ混ぜないでください。

次の改善候補はiPhone実測に基づく待機と加工頻度の調整、輪郭の凹形面積、追跡の対応付け精度です。物理速度を導入する場合は別途キャリブレーションを設計します。ゲーム機能は対象外です。

## v0.4.0 風景認識

`SceneMode` は同じ `RecognitionMode`／`ModeSession` に接続します。`ScenePanel` がメモリ内静止画と加工を担当し、`VisionRenderer` は同じ比較パネルとcontain／鏡像変換を再利用します。静止画はカメラがなくても実行でき、解析要求は最新1件のフラグだけを保持します。未処理画像やカメラフレームを列に積みません。モード・モデル・解像度・入力変更は結果世代を更新します。

`AdaptiveLoad` はv0.3.1の既定挙動を維持しつつ、風景用の待機選択肢と上限15秒をコンストラクタで指定します。TFJSは他モードが読み込まない独立Worker／遅延チャンクに閉じ込めます。Worker終了、GraphModelと一時Tensorのdispose、TFJSエンジンのreset、モデルfetch abortを組み合わせ、互換方式では進行中処理の終了を待ってバックエンドを解放します。

固定原本から実験用内部サイズを作る処理は `scene/resize.ts` で、既知の非学習定数だけを検証して調整します。他のモデルに同じノード名があると推測して再利用しないでください。新モデルにはカテゴリ・重みライセンス・固定URL・容量・ハッシュの独立した定義を追加します。実験記録の風景メタデータは許可した項目だけをJSON/CSVへ出力し、画像を含めません。
