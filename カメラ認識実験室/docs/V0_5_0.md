# Version 0.5.0 — MULTI VISION LAB

## 既存構造の調査と採用方針

`Camera` がMediaStreamの世代管理・Track解放を担当し、`main.ts` の単一 `inFlight` と完了後スケジューラーがキュー蓄積を防止していた。`ModeSession` は初期化を直列化し、切替時に旧モードをdisposeする。これらは再利用した。`displayPanes`／`sourcePoint`／`VisionRenderer` のcontain・鏡像・比較座標、`AdaptiveLoad`、`Rate`、`InferenceStats`、既存localStorage記録も再利用した。

既存エンジンの出力は物体の解析画像ピクセル矩形、通常画像処理の領域・マスク、人物分割のカテゴリ・foreground、風景のカテゴリIDマスクで形式が異なり、横断するフレームIDはなかった。このため複合モード内で同じ所有Canvasを各エンジンへ逐次入力し、正規化アダプターとフレーム照合を追加した。既存の各認識アルゴリズム・モデル・WASMを再実装／変更していない。

静止画の取得・デコード・縮小・blob解放は既存 `ScenePanel` を共有する。複合用の入力上書き値を分離し、画像選択が風景モードの保存設定を破壊しないようにした。比較描画も既存の静止画／加工Canvas経路を複合モードへ拡張した。

## 実装範囲

| 実験 | 再利用する結果・追加する統合 |
|---|---|
| 物体＋色 | EfficientDetの枠内で既存HSV変換・色範囲判定を利用。8色相＋黒白灰の簡易色名、上位3色と指定色割合 |
| 色＋動体 | 既存色領域と背景差分。指定色内の差分を表示し、領域の中心・方向・軌跡・正規化速度を追跡 |
| 複数物体 | 中心間距離、矩形IoU、フレーム間の距離増減、接近／離反の閾値イベント |
| 物体＋動体 | 物体枠内の背景差分マスク占有率。移動の可能性の根拠として表示 |
| 人物＋物体 | SelfieSegmenterの人物foregroundを0.5で二値化し、物体枠内占有率と人物全体の矩形との関係を表示 |
| 時系列認識 | カテゴリと中心距離による対応付け。出現・消失・移動開始／停止、直近100イベント |
| 物体＋風景 | 同じ静止画をEfficientDet→DeepLabへ逐次入力。各物体枠と風景各カテゴリの重なりを枠内割合で表示 |

物体＋風景は静止画専用。他の6実験は静止画／連続を選べるが、動き・時系列の判定は連続だけで実行する。静止画での動体差分は背景基準の初回取得だけで、速度を捏造しない。静止画の指定色・重なりはスナップショット条件として評価する。

## 共通認識インターフェース

`src/multi/fusion.ts` の `EngineResult` はエンジン識別名、フレームID、撮影時刻、処理完了時刻、期限、実測処理時間、`Entity[]`、任意の所有マスクを持つ。Entityはカテゴリ、取得できた場合だけconfidence、正規化矩形・中心・面積、任意のマスク・色割合・追跡情報を持つ。人物・色・動体・風景に物体検出の信頼度を流用しない。

矩形・中心は**未反転の元画像幅・高さに対して各軸0〜1**。人物中心はマスク全体の外接矩形中心。面積は画像全体の割合、人物はマスク画素数、物体は矩形面積。マスクは自分の幅・高さを保持し、正規化した枠をマスク格子へ変換して数える。枠内占有率と2矩形のIoUは異なる値として表示する。風景・動体マスクには取得していない中心距離／IoUを表示しない。

`compatible` はフレームIDと撮影時刻の一致を要求する。連続では撮影からのTTLも検査し、遅い結果を更新時刻で延命しない。静止画は要求した同一画像であるためTTL表示失効を適用しない。`FusionHistory` だけが異なるフレームを明示的な時間差で比較する。カメラ反転は描画・タップの逆変換で処理し、保存する座標系は変えない。

## イベントと追跡

- 初期値: 物体信頼度0.5、指定色・重なり割合0.15、中心距離0.25、速度0.04/秒、継続500ms、割合／距離のヒステリシス0.03。
- 指定色／重なりは上限閾値 `割合＋ヒステリシス` を超えて成立し、`割合−ヒステリシス` 未満で解除する。成立イベントは状態遷移時だけ。
- 接近は `距離−ヒステリシス` 未満への遷移、離反は `距離＋ヒステリシス` 以上への遷移で、継続時間後に発生する。初回から近いだけでは接近イベントを作らない。距離増減の「傾向」は前回との差0.005以上を使い、イベントとは区別する。
- 移動開始は速度閾値以上、停止は閾値の70%未満が継続した場合。速度は検出中心の正規化変化量を撮影時刻差で割る。
- 対象出現には継続した検出が必要。途中で見失った未確定対象は継続時間をやり直す。消失待ちは `max(継続時間, min(TTL,1500ms))`。推論が止まっている間に消失を断定せず、次の有効フレームで判定する。
- 同カテゴリで中心距離0.25未満、TTL内の対象を近い順に一対一対応付け。軌跡30点、イベント100件、消失対象・不要ペアの状態は削除する。
- 実験変更・画像変更・設定の解析条件変更・認識OFF・停止・モード移行で履歴をリセット。表示レイヤーと比較表示だけの変更はリセットしない。

各イベントにISO日時、フレームID、対象ID、数値と閾値を含む根拠を付ける。閾値の状態変化は誤認識をなくす保証ではない。

## 性能・ライフサイクル

単一の所有フレームを順番に解析し、同時に2推論を起動しない。物体＋色／動体は必要な軽量エンジンを保持する。人物＋物体／物体＋風景は物体モデルを解放してから次のAIモデルを初期化し、2つ目も結果取得後に解放する。省メモリを優先するため、この2実験の繰返しには再初期化時間がかかる。

Canvas・Workerはモードdisposeで解放。進行中に共有解析Canvasがリサイズされても入力が変わらないように所有Canvasへコピーする。停止したモードの遅着結果は外側の世代IDと内側のdisposedで破棄する。MediaPipe所有マスクは既存エンジンが有効期間内にコピー・closeし、複合はその配列だけを参照する。

自動負荷調整は既存EWMA（前回75%＋実測25%）の1.5倍を50ms単位で切り上げ、基準待機以上・15秒以下に制限する。完了後の待機なので次の推論開始間隔は処理時間も加わる。手動は200/500/1000/2000ms、解析長辺160/320/480px、TTL1〜15秒。高負荷の案内は実測処理時間に基づき、CPU使用率や電池消費量を推定表示しない。

表示の処理ms・平均／最大にはモデル初期化・逐次推論・統合を含む。エンジン別msは既存エンジンが測定した推論時間（HSVはROIの処理時間）、統合msは整合性検査・関係・追跡・イベント処理で、単純な合計とは一致しない。表示FPSは実描画、推論FPSは完了イベントの既存窓計測。単発のFPSは「—」。

## モデル・配布・記録

新しい依存・モデルは追加していない。MediaPipe Tasks Vision 0.10.21、EfficientDet-Lite0 int8 revision1、SelfieSegmenter square、TensorFlow.js 4.22.0、DeepLab ADE20K／Cityscapes uint8 version1を既存の同一サイト配信で利用。ライセンス・容量・ハッシュは [既存一覧](../THIRD_PARTY_NOTICES.md) と [風景モデル一覧](SCENE_MODELS.md) を継承する。

風景の実験用内部サイズ161/257/385と、既存 `scene/resize.ts` が非学習サイズ定数・プーリングをメモリ内で調整する仕様を維持した。配布原本、学習済みフィルタ、処理コードの変更なし。実際に使用したモデル名と内部サイズを複合の診断・記録にも含める。標準サイズと同じ精度を保証しない。

設定は新キー `camera-vision-lab.multi.v1`。従来のv2・領域・風景設定と旧実験記録を維持する。記録は既存キーで最大50件、複合種類・入力・フレームID・エンジン別時間・統合時間・閾値・関係・イベントを追加。JSON/CSVは明示的な許可項目だけを再構築し、マスク・画像・映像・ファイル名を含めない。最新10件残し／全削除を維持する。保存容量不足時はタブ内で保持しエクスポートする。

同じ静止画の比較用inputIdと、対象ID・カテゴリ・正規化矩形／中心・面積・取得できた信頼度もメタデータとして記録する。inputIdは画像選択・キャプチャ時だけ更新され、各実験を変えても同じ画像なら維持する。推論フレームIDは各解析に固有で、この比較用画像IDとは区別する。

## 制約と次の改善候補

画像内の重なりは接触・把持を意味しない。背景差分は照明・カメラ移動にも反応し、停止した物体も背景との差として残る場合がある。指定色は照明依存、色名は簡易量子化で素材名ではない。追跡は再識別モデルを使わないため、交差・遮蔽・急移動・同カテゴリ複数対象でIDが変わる可能性がある。人物マスクは複数人をまとめた領域で、ランドマークや手指把持判定は未対応。

連続の元映像はライブ、加工は撮影時の所有フレーム。複数エンジンの結果は同じフレームだが、ライブとの遅れは残る。iPhone実機性能・認識精度・長時間メモリ・発熱・物理カメラ切替は未確認。次版は実機測定、追跡対応付け、表示量の最適化、重い実験のモデル切替時間短縮を優先する。学習済みモデルの内部変更は行わない。
