# v0.8.0 — DEPTH LAB

## 採用モデルと実行方式

第一候補のDepth Anything V2 Smallを量子化したONNX Q4を採用。配布元はonnx-community/depth-anything-v2-small、revision `4472b7362082ad9968fee890ca0f1e5aca36b93d`、SHA-256 `5d55b02762e1907589158af3e366bd61ddf648155852a07bbf5e3a074639fcf8`、27,404,416 bytes。SmallはApache-2.0であることを[上流README](https://github.com/DepthAnything/Depth-Anything-V2)と[ONNXモデルカード](https://huggingface.co/onnx-community/depth-anything-v2-small)の両方で確認しています。重み・グラフの変更やSmall以外の採用は行っていません。

ONNX Runtime Web 1.23.2を完全固定し、WASM実行に必要なAPIを実モデルで確認しました。Transformers.jsは前後処理・自動取得の層が追加されるため不採用。既存のRecognitionMode／ModeSession／Workerに直接接続し、同一サイト配信と1スレッドを明示します。これは最新npm版の採用を目的とする更新ではありません。

量子化比較用UINT8は同revisionのmodel_quantized.onnx、27,258,801 bytes、SHA-256 `fcf51f1b230362b28690bb9d1809bf0431f29cad20534e3f589bd7285547f20d`。Q4・UINT8とも演算エラーなく動き、大まかな前後方向は同じでした。小さな鳥と空の区別や絵画の偽の奥行きは、UINT8で解消しませんでした。明らかな互換性問題や一貫した品質改善が確認できないため、第一候補Q4を維持します。Q4の方がファイルは約0.15MB大きく、最小容量だから採用したわけではありません。短時間試行なので両者の優劣や精度を一般化しません。

新規配布は9資産、合計39,719,902 bytes（許諾文含む）。WASM 11,905,541 bytes、MJS合計70,177 bytes、configは36/436 bytes。全出典・ハッシュはpublic/depth-assets.json。MITとApache本文・同梱依存NOTICEを保持します。

## Workerとライフサイクル

DepthMode.initializeは重量アセットを読みません。「奥行きを解析」が要求されて初めてWorkerを作り、同じサイトのORT MJS／WASMとQ4重みを取得。`executionProviders:['wasm']`、`numThreads=1`、proxy=false、WebGPUなし。runtimeファイル名はsimd-threadedですが、1スレッド指定で共有メモリ・追加スレッドは使いません。COOP/COEPなし、crossOriginIsolated=falseのPCブラウザで実モデルを実行しました。[ORT公式環境フラグ](https://onnxruntime.ai/docs/tutorials/web/env-flags-and-session-options.html)を参照。

WorkerとWASM SIMDが使えるSafariが必要です。WebGPUへ無理に変更したり、モデル失敗時に模擬推論へ置き換えたりしません。非対応時はエラーとSafari更新・配置・メモリ確認／再試行を案内します。iPhone実機互換性は未確認です。

既存の単一inFlight、ModeSession世代、resultGenerationと入力IDを再利用。画像差替え・サイズ変更・モード退出・停止でWorkerを終了し、古い結果を表示しません。画像の読込・キャプチャだけでは推論を要求しません。同じ画像の2回目はWorkerのセッションを再利用し、ロード時間を今回の推論時間へ加算しません。タイムアウトは180秒。Tensorは入力・出力ともfinallyでdispose、Worker終了でモデルとWASMヒープを解放します。Canvas・マップ・A/Bもクリアします。

## 前後処理と座標

既存ScenePanelでImageをデコードし、長辺1024px以下のタブ内入力へ変換。ブラウザがデコードした向きをCanvasへ描き、元写真は送信・永続保存しません。モデル入力は長辺280（初期）／392／518、各軸を最も近い14の倍数へ丸めます。元の前処理設定のRGB rescale、ImageNet mean/stdを使用しますが、配布設定の518基準から長辺上限制御・bilinear拡縮へ変更しています。crop・余白はなく、各軸の丸めによる小さな縦横比差だけです。

モデルのFloat32生出力をbilinearで入力写真の解像度へ戻します。色分け・中央値・遮蔽は同じ元画像基準の生マップを使います。DPR・contain余白・左右比較・前面鏡像は既存display.ts／VisionRendererを共有し、余白外タップを無視します。EXIF付きiPhone写真やHEICの実機デコードは別途確認が必要です。

出力は大きいほど手前の相対的な逆深度。実写真の手前道路／遠景、花／空を確認して統一しました。物理単位、推定確率、別写真を横断する尺度ではありません。色分けは画像内min/maxから赤（手前）・緑（中間）・青（奥）へ変換。

A/Bは半径3px（最大7×7）の中央値を使い、差が画像内生出力範囲の4%以下なら「前後を判定しにくい」。これは信頼度百分率ではなく実験上の僅差閾値で、実距離の保証はありません。写真変更・再解析で点を消し、異なる写真の値を比較しません。

ロボットは既存cardArtから背景を除いた自作図形を再利用。キャラクター深度スライダーを同じ写真のmin/max内の閾値へ対応させ、写真の生値が閾値より手前の画素だけでキャラクターのalphaを0にします。等値は隠しません。ON/OFF・ドラッグ・表示切替はCanvas合成だけで再推論せず、位置を動かしても設定奥行きを維持します。

## 実写真と模擬マップの区別

検証用の実写真は上流の固定commit `a561b849ebae10a6f5ef49e26c83cbbcd36c71bf` のassets/examples。demo01は街路、demo02はひまわり、demo03は平面の絵画を写した負例です。scripts/prepare-depth-validation.mjsでハッシュを確認し、Git対象外のdepth-validation.localへ取得します。写真の再配布条件をモデルライセンスから推定せず、写真・深度マップはdistやGit配布資料へ含めません。資料へ残すのは出典と数値メタデータだけです。

- 成功例：demo01の手前道路(0.50,0.95)が遠景建物(0.50,0.38)より大きい。Q4生値は約2.000対0.178。demo02の花(0.33,0.40)は空(0.46,0.18)より手前、約2.320対0。
- 限界例：小さな鳥を含む空のサンプルは0で空との深度差を得られない。平面の絵画demo03にもQ4で約0.188〜2.862の非一様な深度を付ける。描画された形からの推測であり、実際の3D形状とは限らない。UINT8でもこの限界は残りました。
- 未実施：指定された「不透明なコップ・箱・壁」と「コップ／箱を前後交換した」実写真ペア。写真パスの提供がないため、画面位置と前後関係の独立性をこの条件では確認できていません。実機チェックリストへ残します。

ログはdocs/depth-validation/real-q4-*.jsonとquantization-trials.json。後者のp50_95等は写真内の正規化座標であり、写真02/03を道路・建物と呼ぶものではありません。別写真・別量子化の生値の絶対差を距離として比較しないでください。

PC Chromeでは同一写真のロード1856.5ms、初回解析1002.6ms、2回目1026.7ms。複数量子化・写真の試行ではロード約1.8〜3.7秒、長辺280のQ4解析は約1.0〜2.3秒へ変動しました。長辺518（実入力518×350）は解析6082.3ms、ロード2126.6ms。OS・UA・実測値をログに記録し、キャッシュや起動条件を含む変動があるため速度比較の結論には使いません。iPhoneの性能値ではありません。高解像度では時間・メモリが増え、細い境界を失う低解像度との交換条件があります。

模擬マップのテストは明示的なWorker差替えと純粋関数だけで実施し、本番に模擬推論を入れません。部分遮蔽、中央値・僅差、軸の拡縮復元、鏡像・比較座標、画像差替え・モード切替・失敗からの再試行を個別確認します。

## 検証結果

関連ユニット20件成功（depth 6件、既存core 8件、直接共有するscene 6件）。Chromeの関連ブラウザ5ケースは、実Q4の初回／再解析、実写真Q4／UINT8比較、高解像度入力、模擬マップの比較・部分遮蔽、遅着／差替え／モード切替／再試行を別々に検証しています。Edgeも実Q4・模擬遮蔽・遅着／再試行の3ケースが成功し、ロード2144.6ms、初回2038.3ms、2回目1676.6msでした。Chromeでは既存ARカードの実エンジンによるペア・鏡像・停止復帰テスト1件も成功。通常の全件回帰試験は行っていません。

`npm run build`成功。既存39＋新規9の48資産をハッシュ検証し、distへ配置。既存TensorFlow.jsの大きいchunk警告は残ります。親メニューテストはGit配布対象88ファイルだけの一時配置で、既存モード、奥行きの実WASM推論、ARカード印刷／表示／シミュレーターと復帰を確認しました。HTTP・ページエラー・外部要求なし。検証サーバーの.mjs MIMEを補い、JavaScriptとして返すようにしています。GitHub Pagesの.mjs対応は[MDNのモジュール配信説明](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules)で確認できます。

指定されたコップ／箱／壁の2枚、iPhone Safari実機、実カメラの取得・反転、EXIF・HEIC、長時間のメモリ推移は未確認です。成功・失敗例と未確認事項を取り違えないでください。モデル・アプリからの画像送信や自動保存、commit・push・公開は行っていません。
