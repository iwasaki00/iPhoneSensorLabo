# Version 0.3.0 — SEGMENTATION LAB

## 調査と採用

既存の `ModeSession`、単一の解析ループ、共通カメラ、`VisionRenderer`、localStorage設定、モデルの同一サイト配信を調査して拡張しました。既存4モードのアルゴリズムと固定モデル・ライブラリは維持しています。旧フォルダは再作成していません。

MediaPipe Image Segmenterを採用し、既存 `@mediapipe/tasks-vision@0.10.21` とWASMを共有します。追加npm依存はありません。モデルは固定revision 1です。

| モデル | 容量 | 内部入力・形式 | ラベル |
| --- | --- | --- | --- |
| SelfieSegmenter (square) | 249,537 bytes | 256×256 / float16 | 0背景、1人物（信頼度0.5で二値化） |
| SelfieMulticlass 256×256 | 16,371,837 bytes | 256×256 / float32 | 0背景、1髪、2体の肌、3顔の肌、4服、5その他（装飾品等） |

どちらもApache-2.0。出典・容量・推論方式・配布条件はREADMEとTHIRD_PARTY_NOTICESに記載し、モデルのSHA-256と固定URLは `public/assets-manifest.json` に記録しています。モデルは改変していません。ガイドページ本文のライセンスとモデル自体のライセンスを区別しています。

[公式ガイド](https://ai.google.dev/edge/mediapipe/solutions/vision/image_segmenter)、[人物モデルカード](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20MediaPipe%20Selfie%20Segmentation.pdf)、[部位モデルカード](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20Multiclass%20Segmentation.pdf)を参照しました。[iOS SafariのGPUカテゴリ不整合報告](https://github.com/google-ai-edge/mediapipe/issues/6142)を考慮してCPU delegateを選択し、classic Worker優先・メインスレッドCPU互換方式としています。この報告が全iPhone・全バージョンで再現するとは確認していません。

## 実装内容

- 人物: 元映像、強調、人物だけ、背景だけ、白黒マスク。信頼度の閾値付近と空間的平滑化を調整できます。
- 部位: モデルの6ラベルだけを色分け。部位名、占有率、検出／未検出、モデル名を表示します。0.1%未満は未検出です。二値モデルの部位別認識、6カテゴリ以外の目・口・指等は未対応と明示します。
- 背景: ぼかし、単色、端末内の画像差替え、減光。ぼかしはCanvas filterに依存しない画素処理です。
- 部分: 髪・服の輝度を基に色を混ぜ、明暗・質感を可能な範囲で残します。対応部位の対象のみ／対象以外のモノクロにも対応。対象が0.1%未満なら加工せず理由を表示します。
- 比較: 元フレームとマスクを同じ時刻で保持し、加工済みフレームをキャッシュしてrAFで描画。通常／BEFORE／AFTER／左右比較、前面の反転を再利用します。低速推論でも直近の解析フレームを表示します。
- モデル管理: 人物と背景加工は二値、部位と部分加工は6カテゴリ。モデルが同じサブモード間・表示変更では再ロードせず、別モデルに変わる時だけ旧Worker／エンジンを解放します。ロード中は状態を表示し、失敗時もカメラを継続して再試行できます。
- メモリ: 毎回マスクを配列へコピーしてTasks結果をcloseし、ImageBitmapもcloseします。停止時はWorker終了またはTasks close、直近フレームとマスクを解放します。背景画像は長辺960px・ファイル15MBまでで、このタブ内にだけ保持し、専用ボタンで解放できます。
- 設定: 領域用キー `camera-vision-lab.segmentation.v1` を追加。旧キー `camera-vision-lab.v2` の色許容幅・感度・比較表示等を残します。フレームや背景画像は設定ストレージに保存しません。
- 性能: 映像FPS・描画FPS・推論FPSを分離。直近最大120回の平均／最大推論時間、ロードと初期化時間、画像サイズ、フレーム間引き設定、加工時間を追加。推論は同時に1つで、完了後待機して最新フレームを取得します。

## 実機未確認・制約

- iPhone Safariでは未確認。髪・顔・肩・腕・指の境界、動きへの追従、複雑な背景、前後カメラ・回転、メモリ・発熱・バッテリーは [実機手順](IPHONE_CHECKLIST.md)に従って確認が必要です。
- 人物単位のID・人数・個々の指や目・口は出しません。「種類を検出」は背景を除くカテゴリの数で、人数ではありません。
- 人物モデルでは細い毛髪・指・遠方の人物などを失う場合があります。部位モデルも画素単位の正確性を保証しません。照明、逆光、遮蔽、動きで品質が下がります。
- 境界補正は確率閾値と空間ぼかしの近似です。輪郭の漏れ・にじみ・背景ぼかしのハローが残り得ます。
- 色変更は輝度を利用する近似で、元が黒い髪を自然な明るい色へ変換したり、材質を生成するものではありません。
- メインスレッド互換方式は推論中にUIを止める場合があります。初期化中のCPU Tasksは完了待ちになる場合があります。
- 背景画像のデコード形式はSafariの対応に依存します。再読込後は再選択が必要です。透明画像の透明部分は黒を基底として扱います。
- オフライン初回起動、公開先の更新、iPhoneでの初回ネットワークロード時間は未確認です。commit・push・公開は行っていません。

次バージョンは、iPhone実測に基づく適応的な推論間隔、エッジを保つ境界補正、時系列安定化、GPUを使う場合のカテゴリ整合性チェックを候補とします。
